# CLAUDE.md — olive-hac

Conversion work on **one** page: https://olive.kz/l/gosura (slug `gosura`). Olive drives paid
ads to it; the winner of the hackathon is whoever's page produces the most **sales**. Traffic
is overwhelmingly mobile, so the viewport of record is **390×844**.

This is a **mobile CRO project, not a website build.** The page is composed server-side from a
fixed block registry over an MCP endpoint — there is no filesystem deploy.

## Start here

- `research/BRIEF.md` — **verified ground truth**: block registry, config format, business
  data, constraints. Read it before doing anything; don't re-derive what it states.
- `.claude/skills/olive-landing/SKILL.md` — the ship loop (assemble → validate → draft → QA).
- `design/AUDIT.md`, `design/DESIGN_SYSTEM.md` — findings and the spec to build against.
- `plan/ARCHITECTURE.md`, `plan/WORK_PACKAGES.md` — decisions and the build plan.
- `handoff/*.md` — per-role living state (verified facts, decisions in force, gotchas, open
  questions). Read the relevant one before working in that role, and update it after. Whoever
  does the work owns keeping it current, delegated or not.

## Commands

```bash
python3 tools/assemble.py                       # fragments -> landing/config.json (generated)
python3 tools/validate.py landing/config.json   # config is legal? must exit 0 before saving
python3 preview/render.py landing/config.json   # local render
python3 preview/serve.py landing/config.json 8787   # 390x844 + desktop, auto-reload
python3 tools/qa.py <version_id>                # QA what the server actually built

./tools/olive.py show gosura                    # versions and status
./tools/olive.py call meals '{"per_page":100}'  # real data (meals|overview|delivery_zones|…)
./tools/olive.py save gosura landing/config.json --label "..." --status draft
```

`OLIVE_MCP_URL` **must be exported** (`https://olive.kz/mcp/landings/<token>`) — the token is a
credential and is not stored in the repo. The edge WAF 403s default HTTP agents — `olive.py`
sends a browser UA; with `curl` pass `-A "Mozilla/5.0 (iPhone; ...)"`.

## Editing rules

- Edit **fragments**, never `landing/config.json` — it is generated by the assembler.
  `landing/sections/NN-name.json` merge in filename order; `landing/meta/` holds title, theme
  and overrides.
- Custom markup is self-contained and **`gs-`**-scoped (never `sf-` = site, `of-` = funnel).
  The server emits `html` content **raw with no wrapper**, so each block brings its own
  `<section>` and padding. Colors via `var(--l-*, #fallback)`. No external fonts, CDNs or
  images; no inline `on*`.
- **Every CTA needs `data-cta`** — the platform counts conversions by that attribute alone.
  A page without it measures CR 0 no matter how well it converts.

## Hard limits

1. **Drafts only; activation is the user's decision.** Saves never overwrite — each is a new
   version, and `draft` does not change what visitors see. Rollback = activate the previous id.
   **Live baseline: 871.**
2. **Never fabricate** a number, dish, price, review, certification or medical claim. Everything
   traces to an MCP call or the live page. Note "orders" ≠ "fulfilled orders" — a large share
   historically never get paid, so never call them completed.
3. **Never restructure the order form.** In `#order`, `#order-menu`, `#orderFunnel`, `.of`,
   `.sf-form` only `text`/`style`/`addClass` overrides apply. Overrides must never set `id`,
   `name`, `data-*` or `on*` — those carry order logic.
4. Lime `#C4F139` never carries white text (1.31:1 — illegal even for non-text UI).

## Known-bad blocks

`home_quality` renders nothing on a landing. `home_result` claims «400 блюд» while the API
reports 297 dishes. `tools/qa.py` hard-fails both.

## Larger redesigns

Use the agent pipeline in `.claude/agents/`: `landing-design-auditor` (Fable) →
`landing-architect` (Fable) → parallel `landing-implementer` (Opus), one per work package on
disjoint files. Then run the ship loop and report to the user.
